# AlphaRadar 架构说明

基线日期：2026-11-04。范围是 V2 全市场研究系统，加上 Stock Doctor 个股诊断。P0 尚未编码。

技术方案见 [technical-design.md](technical-design.md)。本文保持产品范围和阶段边界。业务架构、表字段、各模块实施方案和 P0 施工在技术方案中。

## 1. 定位

AlphaRadar 供个人研究 A 股。系统每个交易日用程序扫描全市场，筛出未来 5—20 个交易日可能进入主升浪的候选股，再由外部大模型做研究和主观情景判断。用户也可以随时对单只股票做 Stock Doctor 诊断。

程序负责行情、指标、评分、回测和收益统计。大模型负责阅读已落库的事实并写出研究意见。模型不计算指标，不编造行情、筹码和价位，也不做微调。

第一阶段是单用户。行情、因子、评分和预测等事实表不放用户字段。自选、持仓和以后的订阅使用 `owner_id`，放在独立的用户数据上。

## 2. 运行时

浏览器只访问 Nginx。页面由 Vue 提供，`/api` 进入 Java。Java 是唯一业务入口，再通过内网调用量化服务和 Agent 服务。

| 进程 | 技术 | 职责 |
|---|---|---|
| API | Java 21、Spring Boot 3、Spring Security、MyBatis-Plus、Flyway、Maven | 鉴权、配置、任务编排、查询、OpenAPI |
| Quant | Python 3.12、FastAPI、Pandas、NumPy、pandas-ta | 数据适配器、指标、两套评分、回测、收益统计、规则价位 |
| Agent | Python 3.12、FastAPI、模块化工作流 | 统一模型接口、每日研究、多空辩论、诊断解释 |
| Web | Vue 3、TypeScript、Element Plus、ECharts、Pinia、Axios | 展示与输入 |
| 数据 | PostgreSQL 16、Redis 7 | Postgres 保存事实；Redis 只做任务锁和短期缓存 |

指标使用 pandas-ta，保证 Mac 与 Docker 使用同一套纯 Python 实现。XXL-JOB 在 P5 接入；P0 只建立调度配置表。

Java 不调用大模型，也不计算指标。模型客户端只存在于 Agent 服务。数据库记录供应商、模型名、接口地址、超时、任务分配和调用日志；密钥只放在 Agent 容器的环境变量中，表里保存变量名。

## 3. 两条业务链路

每日研究：

1. 适配器把原始数据写入对应的表。
2. 量化引擎按数据截止日计算因子、市场环境、板块强度和牛股评分。
3. 程序按可配置数量筛出候选池。
4. Agent 按层次阅读候选股，写出带证据的研究和主观情景。
5. 持有期走完后，程序用事后行情回填收益。回填结果不改变模型权重。

Stock Doctor：

1. 用户输入代码或名称，系统解析成唯一 `ts_code`。
2. 量化引擎组装该股截止日可见的行情、财务、公告和规则价位。
3. 按诊断模式选择 Agent。
4. 程序计算九维诊断分；模型解释扣分原因和证据。
5. 持仓模式再读取用户输入的成本、数量、仓位和风险偏好。

两条链路共用原始数据和模型接口。诊断分与牛股评分分表保存。

## 4. 模块依赖

| 模块 | 读取 | 写入 |
|---|---|---|
| 行情、财务、公告、新闻适配器 | 外部授权数据源 | 各自原始表，来源可单独替换 |
| 指标、板块、市场环境 | 截止日及之前的原始数据 | 因子、板块日序列、市场环境 |
| 牛股评分与初筛 | 因子和交易状态 | 牛股评分、候选池 |
| 每日 Agent | 已落库事实和带来源的外部文本 | 研究、辩论、主观情景 |
| 表现统计 | 情景记录和之后的日线 | 收益、波动和超额收益 |
| Stock Doctor 程序层 | 单股已落库数据、用户持仓输入 | 诊断分、规则价位、盈亏 |
| Stock Doctor 模型层 | 程序层数据包 | 诊断解释和证据摘录 |
| 调度与提醒 | 交易日历、候选池、告警规则 | 任务日志和提醒 |

外部网页、新闻和帖子只作为资料。它们不能改写系统指令或工具调用。概念关联分成核心受益、直接受益、间接受益、仅概念关联，不能写成真实订单。系统不自动下单。

## 5. 数据规则

- 交易日按上交所日历。5 日、10 日、20 日指交易日。非交易日不运行依赖当日行情的任务。
- 日线保存未复权 OHLC。复权因子单独保存。截止日 T 的指标只用 T 及之前已经存在的复权因子。
- 价格单位是元，成交量是股，成交额是元。换算规则带版本号。
- 财务的可用日是公告日，并区分单季与累计。
- ST、更名、停牌和退市使用当日生效的状态历史。
- 每条外部数据保存来源、采集时间、业务发生时间和可信等级。
- 股东数据同时保存报告期和披露日，按历史持仓展示。
- 资金数据区分可核验记录和第三方估算。第三方主力净流入不写成真实机构流向。
- 没有可靠筹码来源时，筹码集中度和筹码峰标记为缺失。
- 亏损企业不使用负 PE 判断估值高低。估值方法写入诊断记录。
- 支撑位、压力位、止损和止盈参考必须对应一条行情和一条计算规则。历史长度不足时结果为无法计算。

采集适配器负责重试、幂等写入和断点续传。重复执行同一交易日不产生第二行。

P1 的日线和财务选择有授权、能提供公告日和复权因子的数据源。实时行情使用另一个适配器。无偿爬虫不作为生产行情源。

## 6. 两套评分

牛股评分用于全市场排序，规则版本独立：

| 维度 | 满分 |
|---|---:|
| 趋势结构 | 25 |
| 量价资金 | 20 |
| 产业景气 | 15 |
| 基本面 | 15 |
| 资金与股东 | 10 |
| 事件催化 | 10 |
| 市场弹性 | 5 |

分档：85—100 重点关注，75—84 潜在启动，60—74 观察池，60 以下暂不关注。不单独依赖主力净流入。

诊断评分只用于单股诊断：

| 维度 | 满分 |
|---|---:|
| 技术趋势 | 20 |
| 量价关系 | 15 |
| 资金行为 | 10 |
| 基本面 | 15 |
| 估值水平 | 10 |
| 消息催化 | 10 |
| 产业竞争力 | 10 |
| 市场情绪 | 5 |
| 风险控制 | 5 |

风险控制分越高，表示已经证实的风险越少。两个评分都要求维度可单独查看、依据可追溯、权重可配置、带规则版本。缺数据的维度留空，不补满分，也不把其他维度重新摊成 100。两个分数都不表示上涨概率。

## 7. 模型协作

`LlmProvider` 实现在 Agent 服务，包含 Grok、OpenAI、Claude、Gemini。业务代码通过任务代码选择模型和数量，默认分配可改：

| 层次 | 默认职责 |
|---|---|
| 程序 | 扫描全市场并计算评分 |
| 量化筛选 | 约 100 只候选 |
| Grok | 海外产业信息和 X 公开帖子 |
| GPT | 深度研究和最终汇总 |
| Claude | 风险、反方和证据审查 |
| Gemini | 备用与交叉验证 |

每次调用记录模型名、版本、提示词版本、token、费用、耗时和状态。失败有超时、重试、限流和降级。提示词按版本保存，执行记录钉住当时的版本。

每日研究的结论分成事实、推断和不确定性。多空辩论保留双方证据、争议点、已确认事实和未证实信息。模型投票不能代替来源核验。

主观情景保存 5 日、10 日、20 日的乐观、中性和悲观情景，以及结论、风险条件和价位引用。记录类型固定为 `subjective_scenario`。新结论追加记录，不覆盖旧结论。

X 和社交媒体默认为 D 级证据。没有原始链接、无法区分首次发布时间的内容，不进入事实列表。

## 8. Stock Doctor

诊断模式：

| 模式 | 时间重点 | 模型重点 |
|---|---|---|
| 全面诊断 | 全部维度 | 全部解释步骤 |
| 短线交易 | 未来 1—20 个交易日 | 技术、量价、资金、消息、情绪、风险 |
| 中线投资 | 未来 1—6 个月 | 基本面、估值、消息、产业链、股东、风险 |
| 持仓诊断 | 用户持仓 | 盈亏、技术、风险和持有条件 |

未列入的维度仍展示程序已经算出的结果，不为它们额外发起长调用。执行清单放在 `diagnosis_agent_plan`。

程序步骤：解析股票、取数、技术指标、量价统计、财务比率、估值比率、规则价位、诊断计分、持仓盈亏。

模型步骤：Technical、VolumePrice、Capital、Fundamental、Valuation、News、Industry、Holder、Sentiment、Risk、Decision。Risk 不把其他步骤的看多结论当事实。Decision 只汇总已有证据。

消息证据等级：

| 等级 | 范围 |
|---|---|
| A | 公司公告、交易所公告、监管正式文件 |
| B | 定期报告、公司官方新闻、正式行业协会资料 |
| C | 权威媒体、可信行业研究 |
| D | 个人社交媒体、论坛、未经证实的传闻 |

D 级证据单独出现时，不能支撑消息催化高分。

趋势阶段由程序根据指标规则给出：底部震荡、底部反转、趋势启动、主升浪、加速上涨、高位震荡、趋势转弱、下跌趋势。模型可以解释，不能改写阶段枚举。

持仓诊断保存成本、数量、仓位比例、投资周期和风险偏好。市值、盈亏和盈亏比例用诊断引用的收盘价计算。继续持有、减仓、补仓和退出各自保存确认条件。浮亏本身不构成补仓条件。

诊断覆盖十二个分析面：市场环境、技术、量价、资金、筹码、基本面、估值、消息、产业链、股东、情绪、风险。风险结论列出最多三个已由证据支持的因素。

## 9. 数据库

每张表包含主键、`created_at`、`updated_at`、`source`，以及业务唯一索引。行情查询索引为股票代码加交易日。

P0：

- `trading_calendar`：交易所 + 日期。
- `llm_provider`：供应商代码。保存地址、模型名、密钥变量名、超时和能力。
- `llm_prompt`：提示词代码 + 版本。
- `llm_task_route`：任务代码 + 版本。保存供应商、模型和数量上限。
- `system_schedule`：任务代码。保存 cron、`Asia/Shanghai`、是否依赖交易日。

P1：

- `stock_basic`：`ts_code`。身份、交易所、上市日和退市日。
- `stock_status_hist`：代码 + 生效日。名称、ST 和交易状态的历史。
- `stock_daily_quote`：代码 + 交易日 + 来源。未复权行情、市值、涨跌停和当日状态。
- `stock_adj_factor`：代码 + 交易日 + 来源。
- `index_daily`：指数代码 + 交易日 + 来源。至少包含上证指数、深证成指、创业板指、沪深300、中证1000。
- `stock_financial`：代码 + 报告期 + 报告类型 + 来源。公告日必填，区分单季和累计。
- `stock_minute_quote`：代码 + 时间 + 周期 + 来源。P1 只建表。
- `data_ingest_checkpoint`：来源 + 数据集。

P2：

- `stock_factor`：代码 + 交易日 + 因子代码 + 版本。
- `stock_score`、`stock_score_detail`：牛股评分和七个维度。
- `sector_basic`、`sector_stock_relation`、`sector_daily_quote`。
- `market_environment`：交易日 + 规则版本。程序写入市场状态和涨跌停统计。

P3：

- `stock_announcement`、`stock_news`、`stock_news_link`。
- `agent_task`、`agent_execution`、`agent_research_report`、`agent_debate`。
- `llm_call_log`。
- `stock_diagnosis`、`stock_diagnosis_dimension`、`stock_diagnosis_level`、`stock_diagnosis_evidence`、`user_holding_input`。
- `diagnosis_agent_plan`：模式 + 版本。

P4 及以后：

- `stock_prediction`：只追加。钉住行情日期、评分版本、Agent 版本、模型版本和提示词版本。
- `stock_prediction_result`：一条预测一行。程序写入 1、5、10、20 日收益、最大有利波动、最大不利波动和相对沪深300超额。
- `stock_holder`：数据源确定后定唯一键，同时保留报告期和披露日。
- `stock_watchlist`：`owner_id` + 股票。
- `stock_alert`：只追加。

海外市场序列不写入 A 股日线表，在 MarketAgent 使用前单独建表，并保留来源和观测时间。

## 10. 自动任务

全部使用北京时间，交易日判断来自 `trading_calendar`。

| 时间 | 任务 |
|---|---|
| 08:30 | 海外市场与产业信息，整理可能影响 A 股的催化 |
| 09:35 | 开盘行情、高开低开、板块异动、重点股信号 |
| 10:30 | 放量突破、主升浪启动和资金异动 |
| 14:30 | 尾盘行为、趋势变化和风险提醒 |
| 15:30 | 日线、指标、全市场评分和候选池 |
| 20:30 | 公告、新闻、多 Agent 研究、重点股辩论和次日观察名单 |

任务支持手动触发、定时触发、失败重试和执行日志，重复触发保持幂等。

## 11. 前端

首页展示指数、市场环境、热点板块、牛股前十、主升浪信号和风险。股票页展示 K 线、成交量、MACD、RSI、KDJ、均线、牛股评分、研究报告、辩论和历史情景。诊断页提供四种模式、九维分数、证据等级、规则价位和持仓输入。板块页展示强度、轮动、龙头和产业链映射。管理页展示模型配置、调用成本、提示词版本和任务状态。预警中心展示启动、突破、转弱、公告、业绩和资金异动。

P0 只保留能打开并显示服务健康状态的首页。

## 13. 阶段

| 阶段 | 完成标准 |
|---|---|
| P0 | Postgres、Redis、API、Quant、Agent、Web 能够启动，基础表迁移可重复执行 |
| P1 | 可以查询全 A 股主数据和历史日线，财务带公告日 |
| P2 | 每个交易日生成可追溯的牛股候选池和规则价位 |
| P3 | 输入一只股票，能生成研究报告、多空辩论和诊断结论 |
| P4 | 能查看历史情景和之后的真实收益、模型表现 |
| P5 | 按交易日历自动执行并提醒，无人值守 |
| P6 | 首页、研究、诊断、板块、Agent 管理和预警中心可稳定访问 |

P0 的实现顺序是：Compose 和环境变量样例，Flyway 五张基础表，Java 健康检查与本地登录，两个 Python 服务的健康检查和 OpenAPI，Vue 首页与 Nginx 反代。账号、数据库口令和模型密钥都来自环境变量，不进入 Git。
